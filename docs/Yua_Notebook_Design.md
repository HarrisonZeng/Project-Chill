# Yua 的小本子 — 活的任务本设计（owner 提案 2026-08-20）

## 一句话
她的小本子不只写「我的小项目」。上面还有她的日常待办（收衣服、给店里补货单、回妈妈消息……），
**玩家看得见**。现实时间过去一天以上再回来，她会把某些项划掉，开场时顺口提一句——
「昨天终于把衣服收了」「进货单还没写，别提了」——让她像个真实在过日子的人，
也给游戏持续产出「她的生活」内容。

## 为什么值得做
- 现在「她有生活」全靠台词讲。本子是**可视的**生活证据，比台词便宜、比台词可信。
- 它天然产出回访内容：每次回来都有一两句新鲜的「她这几天」，不用写剧集。
- 它是写作线的温床：『我的小项目』永远挂在本子上，偶尔被划掉又重新写上（「又拖了」），
  玩家看着就懂她的回避，不用她解释。

## 代称决定（取代「那个东西」）
本子上那一行写：**「我的小项目」**（也可以随关系进展换措辞，见下表）。
台词里她这么指代：「本子上那个小项目」「我自己的那个项目」「我的 side project」——
都比「那个东西」自然。她**不说内容**，但也不神秘兮兮；被问就「……先不说，有点不好意思」。

| 阶段 | 本子上的那一行 | 她嘴里怎么说 |
|---|---|---|
| Ep0–Ep4（未坦白） | 我的小项目 | 「本子上那个小项目」「我自己搞的一个小东西，先不说」 |
| Ep5 坦白后 | 写一章 / 改第三章 | 「我的小说」「那章」 |
| 后期 | 投稿前最后一遍 | 直说书名（占位） |

## 本子内容规则
- 固定在顶上：「我的小项目」（永远在，划掉又重写，是她的回避可视化）
- 日常 2–3 条，随机从池子抽，按**现实日期**轮换：
  - 生活池：收衣服 / 买洗衣液 / 回妈妈消息 / 给绿萝浇水 / 修台灯 / 洗杯子（一周了）
  - 书店池：写三张荐书卡 / 补进货单 / 擦咖啡机 / 新书上架 / 调拉花
  - 副业池（水族馆登场后才解锁）：周六早班 / 给小七的杯子洗一下
  - 游戏池：别打游戏（反复出现，反复被划掉又写上——梗）
- 她不会写「学习」类条目，她的正事就是小项目。

## 回访机制（引擎）
- 存档记 `notebook_items: [{text, added_day, done_day|null}]` + `last_notebook_day`。
- 玩家回来时，若 `today - last_notebook_day >= 1`：
  1. 对 1–2 条已有条目掷骰：完成（划线）/ 拖延（加个「…」）/ 新增一条。
  2. 「我的小项目」有 30% 概率被划掉再重写（= 她又开了文档又关了）。
  3. 开场问候之后，她顺口提**一条**变化（只一条，不列清单）：
     - 完成：「对了，衣服终于收了。说出来给自己记一功。」
     - 拖延：「进货单……别看我本子，我知道。」
     - 小项目划掉重写：「那个小项目嘛……今天开了又关了。别问。」
  4. 这些句子**走脚本池**（每条目一两句变体），AI 不参与——便宜、稳定、可控。
- 同一天内多次打开：本子不变、不重复提。

## 口味约束（沿用口味档案）
- 提变化时只提一条、一句话带过、自嘲不苦情。
- 绝不说「你呢？你的待办完成了吗」——不查岗。
- 划线的视觉要轻（一道细线），别做成成就系统。

## 工程量估计
- 数据：`data/dialogue/notebook_pools.json`（池 + 变体句）
- 引擎：`notebook_manager.gd`（日期判定、掷骰、持久化）≈ 150 行
- UI：任务面板已有；加「她的区域」渲染 + 划线样式
- 接入：greeting 之后插一拍「提一条变化」
- 时机：Ep0–3 剧本定稿后做，赶在 demo 视频前（它是「她是活的」的最佳镜头素材）
