# Type Mode Design — 自然化方案（2026-08-09，回应 owner 反馈 #3 #4）

Owner 的两个观察，作为本文档的出发点：
1. Yua 提到「按钮」「回到按钮回复」是 OOC（出戏）——她不该知道玩家的 UI 长什么样。
2. Type Mode 是这个游戏的独特卖点，应该更早出现（甚至 EP0 取名时就反应），
   并且部分节点应该「只能打字」，让过渡更自然、也逼玩家体验到核心特色。

---

## 0. 已经改掉的（本次代码修改，可直接验收）

| 原来 | 现在 |
|---|---|
| AI 回复后出现「回到按钮回复」「再写一句」两个片 | 什么片都不出。她说完就自然回到共处；想继续说就继续打字，想结束就点她或开计时 |
| AI 失败兜底句「嗯。那先用按钮走吧，简单一点。」 | 「唔……刚才这边卡了一下，没听清。再说一遍？」（当成通话卡顿，戏内） |
| 进入 Type Mode 时的英文系统提示 + 「回到按钮回复」片 | 只有她的一句「嗯，你说，我听着。」，无片、无系统提示 |
| Type Mode 中点她：「……也可以回到按钮。」 | 「我在。你慢慢想，不急。我先写我这段。」 |
| 点她会重开问候甚至重播 EP0 | 每次会话只开场一次；之后点她 = 短的「我在」类反应线（新语料池），永不重播剧情 |

**核心原则（以后所有台词都照此检查）：**
Yua 是这个自习通话软件的另一个用户。她可以提「计时器」（她自己也在用的东西），
但她永远不知道玩家屏幕上有什么按钮、选项、输入框。她只知道：对面这个人会「说话」。

## 1. EP0 取名反应（owner 提议，采纳并扩展）

玩家在 ep00_name 输入昵称后，Yua 先反应一下，再进 ep00_close。这是玩家对
「这个游戏和视觉小说不一样」的**第一次感知**，也是 D3 阶段一（概念视频）里最好拍的镜头。

### 两层实现（缺 AI 时不塌）

**AI 层（有 API key 时）：** 一次受限调用 —— 上下文=「玩家刚告诉你 ta 的称呼」，
规则=1–2 句、好奇但不评判、不追问真名、不发表身份猜测以外的内容。超时 1.5 秒即放弃转脚本层。
效果即 owner 设想：真名感 →「哦？听起来像本名。那我就直接这么叫了？」；
动漫感 →「……这个名字，是不是在哪部里见过。你喜欢那个角色？」；
整活名（无敌暴龙）→「……好、好的，暴龙。那我以后认真喊你这个，你别后悔。」

**脚本层（无 key / 超时兜底）——纯启发式三选一，JSON 节点：**
- `ep00_name_react_short`（≤3 个汉字或 ≤10 个字母，正经取名的样子）：
  「{name}……嗯，好记。\n\n那就这么叫了。」
- `ep00_name_react_playful`（含数字/超长/含「王」「帝」「无敌」「大魔王」「酱」「大人」等）：
  「…………{name}。\n\n行，很有气势。我尽量绷住认真喊。」
- `ep00_name_react_default`（其他）：「{name}。\n\n嗯，念起来还挺顺的。」

之后都汇入 ep00_close（她用 {name} 收尾那句照旧）。

### EP0 里更早的 Type Mode 体验

取名本身**就是**第一次打字——所以顺水推舟：ep00_close 之前加一个可跳过的自由输入拍：
她说「对了，随便说一句什么吧。什么都行——就当试试话筒。」
- 玩家打字 → AI/兜底回一句轻的 → 进 ep00_close
- 玩家直接点她/点继续 → 「不说也行。反正以后有的是机会。」→ ep00_close
不设任何必答；符合「无强制任务」红线。

## 2. 玩家行为 → Yua 反应总表（Type Mode 全流程）

| 玩家做了什么 | Yua 的反应 | 状态 |
|---|---|---|
| 在 (自己写) 类节点打字 | AI 回 1–3 句 → 无片，自然坐回 | ✅ 已实现 |
| AI 回复后继续打字 | 继续对话（同模式），她永远不下逐客令；戏内边界=她自己也要写东西：聊 3–4 轮后她的回复应自然变短、出现「我这段还没写完」 | 🔜 轮数递减规则写进 runtime rules |
| 打空内容 | 不发送（现状） | ✅ |
| 专注计时中打字 | 不调 AI，用 focus_click 冷却池（「……响了再说」） | ✅ 已有 + 冷却已修 |
| Type Mode 中点她 | 「我在。你慢慢想，不急。」类 | ✅ 已修 |
| 会话已开、无对话时点她 | idle_click 池（「嗯？我在。」）；首次专注前用 prefocus 池轻推计时器 | ✅ 本次新增 |
| 问她写的是什么（ep05 前） | AI 规则已有 writing_disclosed 门：不承认、含糊带过（「就……随便记点东西」） | ✅ 规则在 context packet |
| 问「你是 AI 吗」 | 规则已有 Never say you are an AI；戏内答法写进 persona：「……怎么突然问这个。我在你对面坐着呢。」 | 🔜 persona 补一行 |
| 说了沮丧/压力大的话 | 轻接住+不做心理咨询：「听起来today确实够呛。……先不解决它，坐一会儿就好。」不诊断、不建议专业事项 | 🔜 runtime rules 补一段 |
| 辱骂/越界内容 | 冷而不斥责：「……这样的话，我就先做我的事了。」然后当次不再回复 | 🔜 runtime rules 补一段 |
| 打了很长一段 | 她只回应重点+1 句，不逐条点评（保持 1–3 句上限） | ✅ 规则已有 |

## 3. 「只能打字」的节点（type-first episodes）

Owner 方向：这些入口去掉按钮片，只留输入框，让体验更自然、并保证玩家接触 Type Mode。

采纳，但留一个安全阀：**首次**遇到 type-first 节点时她把「可以不回」说在台词里
（「不想说就摆摆手，我不介意」——点她=摆摆手，走 idle_click 池），这样不打字的玩家永远不会卡死。

建议 type-first 化的现有入口（去掉旁边的按钮片）：
- ep04_01「我说说我的办法（自己写）」→ 整个节点仅输入框 + 台词尾句给出摆手出口
- ep07_01「有，我告诉你一个（自己写）」→ 同上
- ep11 / ep13 / ep14 的 (自己写) 入口 → 同上
- ep01–ep03 的三选一**保留按钮**（刚结束专注时点选择比打字省力；节奏考虑）
